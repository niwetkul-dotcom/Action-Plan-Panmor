# ระบบเขียนและรายงานโครงการ — โรงเรียนบ้านปั้นหม้อ

WebApp แบบ SPA สำหรับจัดทำโครงการและเชื่อมข้อมูลกับ Supabase โดยใช้ React, TypeScript, Vite และ GitHub Pages ไม่มี Google Apps Script หรือ Google Sheets เป็น backend

รุ่นนี้เป็น **ฐานระบบที่รันได้และเชื่อมฐานข้อมูลจริงเมื่อเจ้าของระบบตั้งค่าแล้ว** ไม่ใช่ระบบบัญชีครบทุกวงจร และยังไม่ผ่านการทดสอบบน Supabase project ของโรงเรียน ห้ามใช้ยอดหรือเอกสารจากรุ่นนี้เป็นหลักฐานทางการจนกว่าจะตรวจสิทธิ์และทดสอบกับผู้ดูแลโรงเรียน

## สิ่งที่มีในรุ่นนี้

- Supabase Auth สำหรับเข้าสู่ระบบและ session; ไม่มีการสร้างบัญชีตัวอย่างหรือรหัสผ่านร่วมกัน
- SPA ใช้ HashRouter, lazy route loading และ Vite base path สำหรับ GitHub Pages
- Dashboard และรายการโครงการค้นหา/กรอง/แบ่งหน้าจาก Supabase ตาม RLS
- แบบโครงการ 6 ขั้น บันทึกโครงการ กิจกรรม รายการงบและตัวชี้วัดผ่าน RPC ธุรกรรมเดียว; ส่งพิจารณาผ่าน RPC
- Workflow อนุมัติโครงการและคำขอใช้เงินหลายขั้น พร้อมลายเซ็นในขั้นพิจารณา
- คำขอกิจกรรม, บันทึกจ่าย, รับคืน/กลับรายการผ่าน SQL RPC พร้อมตรวจยอดและ idempotency
- หน้าทะเบียนงบประมาณอ่านจาก views ที่คำนวณบนฐานข้อมูล ไม่ให้ client เขียนยอดคงเหลือเอง
- รายงานร่างและรายการ CIPP ใช้คำตอบจริง แสดงค่าเฉลี่ย/ร้อยละคะแนนเต็ม/ระดับ/เกณฑ์เริ่มต้น 4 จาก 5 และ sample S.D.
- หน้าผู้ดูแลสำหรับข้อมูลโรงเรียน ปีงบประมาณ รายการอ้างอิง และกำหนดบทบาทบัญชีที่มีอยู่
- SQL migrations, RLS และ Storage policies; ห้ามนำ `service_role` หรือ DB password ไปใส่ในเว็บ
- พิมพ์สรุป CIPP พร้อมรอโหลดฟอนต์และตรวจภาพก่อนเปิดหน้าพิมพ์

ไม่มีโครงการ กิจกรรม ผลประเมิน ลายเซ็น หรือยอดเงินจริงตัวอย่างในฐานข้อมูล การที่ตาราง `activities` ว่างเป็นผลที่คาดได้ก่อนผู้ใช้บันทึกโครงการพร้อมชื่อกิจกรรม ระบบจะแจ้งในหน้าเขียนโครงการเมื่อยังไม่มีชื่อกิจกรรม

## ขอบเขตที่ต้องทำต่อก่อนใช้จริง

ข้อกำหนดแนบมีขนาดใหญ่กว่ารุ่นนี้ และฟังก์ชันต่อไปนี้ยังทำไม่ครบ:

- อัปโหลดตราโรงเรียน/ตราครุฑ/ฟอนต์ เอกสารราชการฉบับเต็มและ snapshot ที่ตรึงทุกค่าตาม revision
- หน้าสร้างกรอบวงเงินและการขอเพิ่ม/ลดวงเงินที่มี workflow อนุมัติ
- รายงานกิจกรรมฉบับเต็ม, PDCA, ตัวชี้วัดผลจริง, ความพึงพอใจ, ภาคผนวกรูป และ CIPP แบบแม่แบบ/แยกผู้ประเมินกับยอดสรุป
- หน้าจัดการบุคลากร/เชิญบัญชี, ผู้ปฏิบัติแทน, notifications, audit log viewer และการปิดโครงการ
- คลังแบบฟอร์มการเงิน, ระบบนำเข้าข้อมูลแบบ dry-run และตรวจยอดก่อน/หลังย้าย
- integration tests ที่เชื่อม local Supabase, ทดสอบ RLS ทุก role และทดสอบ Storage จริง

หน้าตั้งค่าที่ทำไว้ใช้กับการกำหนดข้อมูลพื้นฐานเท่านั้น การเชิญบัญชีใหม่ยังต้องทำผ่านช่องทาง Supabase ที่ผู้ดูแลโรงเรียนควบคุม และลายเซ็นภาพไม่ใช่ลายมือชื่อดิจิทัลที่มีใบรับรอง

## เริ่มต้นใช้งาน

ต้องใช้ Node.js 24 ขึ้นไปและ npm

1. สร้าง Supabase project ของโรงเรียนและติดตั้ง Supabase CLI
2. จากโฟลเดอร์นี้ ลิงก์ project และนำ migration ทั้งหมดไปใช้:

   ```sh
   npx supabase login
   npx supabase link --project-ref <PROJECT_REF>
   npx supabase db push
   ```

3. สร้างบัญชีผู้ดูแลคนแรกผ่าน Supabase Auth จากนั้นกำหนดสิทธิ์ให้ UUID ของบัญชีนั้นใน SQL Editor:

   ```sql
   insert into public.role_assignments (school_id, user_id, role)
   values ('b0000000-0000-4000-8000-000000000001', '<AUTH_USER_UUID>', 'admin');
   ```

   ห้ามเปิด self-registration ให้ผู้ใช้ทั่วไปได้ role อัตโนมัติ

4. ผู้ดูแลเพิ่มปีงบประมาณจริงในหน้า “ตั้งค่าและข้อมูลพื้นฐาน” ก่อนเขียนโครงการ ข้อมูลวันที่ต้องเป็น ค.ศ. ในช่อง date; หน้าจอแปลงเป็นปีไทยเมื่อแสดงผล
5. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่เฉพาะ URL และ publishable key:

   ```sh
   cp .env.example .env.local
   npm ci
   npm run dev
   ```

   อย่าใส่ `service_role`, รหัสผ่านฐานข้อมูล หรือ access token ใน `.env` ที่ขึ้นต้นด้วย `VITE_`, source code หรือ GitHub

## GitHub Pages

- ตั้ง repository variables `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY`
- เปิด Pages source เป็น GitHub Actions แล้ว push ไป branch `main`
- workflow คำนวณ Vite base path ตามชื่อ repository, build, test, lint และ deploy ผ่าน Actions
- SPA ใช้ HashRouter เพื่อให้ลิงก์ย่อยเปิด/refresh ได้บน GitHub Pages

## ตรวจสอบในเครื่อง

```sh
npm ci
npm run build
npm test
npm run lint
```

การ build/test ในเครื่องไม่ยืนยันการทำงานกับ Supabase จริง ก่อนใช้งานต้องทดสอบ role assignments, Auth, RLS, Storage, workflow, การคืนเงิน/กลับรายการ และยอดเงินกับข้อมูลโรงเรียนจริง โดยผู้รับผิดชอบที่ได้รับอนุญาต
